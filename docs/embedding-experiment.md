# 임베딩 방식 비교 실험 (STEP 3-0 결정 근거)

> ※ 이 기록은 청크 14개(자료 확장 전) 기준이다. 청크를 17개(NE-015~017 추가)로 늘린 뒤의 재측정은 `docs/corpus-expansion.md`에 있다.

모델 `onnx-community/embeddinggemma-300m-ONNX`(dtype q8)을 두 가지 방식으로 쓰고 같은 청크 14개, 질문 10개로 비교했다.
재현: 프로젝트 루트에서 `node scripts/compare-embedding.mjs 결과.txt`

| 방식 | 설명 |
|---|---|
| A | `pipeline("feature-extraction")` + `{ pooling: "mean", normalize: true }` (수업 가이드 방식) |
| B | `AutoTokenizer` + `AutoModel`의 `sentence_embedding` 출력 (모델 카드의 공식 예시) |

입력 형식은 둘 다 모델 카드의 형식이다. 문서는 `title: 섹션 | text: 본문`, 질문은 `task: search result | query: 질문`.

## 결과

- 차원은 둘 다 768, 벡터 크기(노름)는 둘 다 1.0000.

"노을은 사람이에요?"는 두 방식 모두 NE-001(페르소나 소개: "AI 페르소나입니다")을 1위로 했는데, 이 청크도 질문에 맞는 근거다. 이 질문을 정답으로 인정하면 B는 8/8, A는 "실명이 뭐예요?"를 놓쳐 7/8이다.

## 결정

**B(`sentence_embedding`)를 쓴다.**
- 모델 카드의 공식 방법이다.
- 무관한 질문의 점수가 낮고 점수 폭이 넓어, "관련 자료가 약함"을 가르기 쉽다. A는 무관한 질문(0.505)이 일부 관련 질문(0.560)에 바짝 붙는다.
- "실명이 뭐예요?"처럼 경계 질문에서 A는 엉뚱한 청크(NE-007)를 1위로 올렸다.
- A·B 벡터는 호환되지 않으므로, 벡터 저장소에 `method`를 기록해 방식이 다르면 검색을 거부한다.

## 한계

- 청크 14개, 질문 10개(관련 8, 무관 2)의 작은 실험이다. 경향이지 성능 비교가 아니다.
- q8만 시험했다. fp32와의 차이는 이 방식(B)에서 측정하지 않았다.
- 기준점(약한 근거)은 이 값에서 정하지 않고 STEP 4에서 질문을 더 늘려 정한다. 수업 가이드의 0.55는 A 방식의 값이라 B에는 그대로 맞지 않는다(B의 관련 질문 최저가 0.317이다).
