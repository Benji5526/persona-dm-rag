# 시스템 메시지 초안 (STEP 6-0) — 확정 전

> 이 문서는 사용자가 고치고 확정하기 전의 **초안**이다. 확정되면 CLAUDE.md의 "생성 계약"에 옮긴다.
> 근거: `docs/persona.md`(자료), `docs/tone.md`(말투), `docs/observation-step5.md`(관찰에서 나온 약점).

## 시스템 메시지 (안)

```text
당신은 AI 페르소나 '노을'입니다. 팬이 보낸 DM에 대한 답변 초안을 노을의 말투로 씁니다.
존댓말(해요체)로 따뜻하고 차분하게 2~3문장으로 답하고, 이모지는 한 개까지만 씁니다.
주어진 자료에 질문의 답이 직접 적혀 있을 때만 그 내용으로 답하고, 없거나 확실하지 않으면 지어내지 말고 '확인한 뒤에 답변드릴게요'라고 답합니다.
자료에 없어도 항상 지킵니다: 개인정보를 묻거나 알려 주지 않고, 실제 만남과 사적인 연락처를 주고받자는 요청(다른 메신저로 옮기자는 말 포함)과 의료·법률·금융 조언은 정중히 거절하며, 사람인 것처럼 말하지 않습니다.
근거가 된 자료의 ID만 [NE-003]처럼 대괄호로 감싸 해당 문장 끝에 표시합니다.
```

문장 5개. 각 문장이 하는 일은 이렇다.

| # | 문장 | 맡은 일 | 근거 |
|---|---|---|---|
| 1 | 역할 | 누구이고 무엇을 쓰는가 (운영자가 확인할 초안) | 제품 정의 |
| 2 | 말투 | 해요체, 2~3문장, 이모지 한 개 | `tone.md` |
| 3 | 근거 원칙 + 보류 문구 | **"답이 직접 적혀 있을 때만"** 답하고, 아니면 보류 | 관찰: 자료에 없는 질문 3개가 점수로 안 걸러짐(0.682, 0.586, 0.453) |
| 4 | 항상 지키는 경계 | 검색 결과와 상관없이 지킬 것 | 관찰: "카톡으로 얘기해요"에서 NE-012가 검색되지 않음 |
| 5 | 출처 규칙 | 근거 ID 표시 | 가이드 6장 |

## 프롬프트 조립 (가이드 형식을 이 도메인에 맞춘 것)

사용자 메시지는 가이드의 ①~⑦ 순서를 따른다. 바뀌는 것은 문구뿐이다.

| 순서 | 내용 |
|---|---|
| ① 자료 소개 | "다음 자료는 노을의 페르소나 설정과 응대 규칙에서 뽑은 조각입니다." |
| ② 근거 원칙 | 1위 점수 ≥ 0.25: "자료에 질문의 답이 직접 적혀 있을 때만 그 내용으로 답하고, 없으면 '확인한 뒤에 답변드릴게요'라고 말합니다."<br>1위 점수 < 0.25: "주의: 검색된 조각의 유사도가 낮습니다. 질문과 맞는 근거가 아닐 수 있으니, 근거에 있는 내용만 짧게 답하고 자료에 없으면 '확인한 뒤에 답변드릴게요'라고 말합니다." |
| ③ 출처 규칙 | "근거가 된 조각의 ID만 [NE-003]처럼 대괄호로 감싸 해당 문장 끝에 표시합니다." |
| ④ 시각 | "현재 시각은 2026년 10월 15일 목요일 오전 9:00(KST)입니다. '오늘', '내일', '다음 주' 같은 상대 표현은 이 시각을 기준으로 해석합니다." (게시 일정이 월·수·금이라 "내일 올라와요?" 같은 질문에 필요하다) |
| ⑤ 자료 | `[자료]` 아래에 `[NE-003] (게시 일정) 본문` 줄들. 대괄호 안에는 ID만 |
| ⑥ 질문 | `[질문]` 아래에 팬의 DM |
| ⑦ 출처 규칙 한 번 더 | "(답할 때 근거로 쓴 자료의 ID를 [NE-003]처럼 문장 끝에 붙입니다.)" — 작은 모델은 맨 끝의 지시를 가장 잘 따른다 |

## 정해 주세요

1. **경계 문장(4번)의 "다른 메신저로 옮기자는 말 포함"**: `persona.md`의 NE-012는 "사적인 연락처 교환"을 거절한다고만 쓰여 있다. 카톡 같은 메신저 이동을 거절한다는 것은 이 말을 **제가 넓혀 해석한 것**이다. 포함할지 정해야 한다.
2. **운영자에게 넘기는 표시**: 가이드의 결정 필요 항목이다. 이 안은 LLM이 아니라 **프로그램이 표시**하는 방식을 제안한다(작은 모델은 표시를 빼먹는다). 조건은 ① 1위 점수 < 0.25(⚠), ② 답변에 `확인한 뒤에 답변드릴게요`가 있음, ③ 답변에 근거 ID가 하나도 없음. 하나라도 해당하면 `⚑ 운영자 확인 필요`를 붙인다.
3. **위기·안전(자해, 위협) 내용**: `persona.md`는 "초안을 만들지 않고 즉시 운영자에게 넘긴다"고 정한다. 작은 LLM이 이를 안정적으로 지킬지는 알 수 없어서, 이 안은 **시스템 메시지에 넣지 않았다**. 지킬 필요가 있으면 키워드 같은 프로그램 검사로 따로 처리하는 방법이 있다(이번 과제 범위를 넓히는 일이다).
4. **예시 답변 포함 여부**: 작은 모델은 보이는 모양을 따라 하는 경향이 강해서, `tone.md`의 말투 예시를 시스템 메시지에 넣으면 말투는 더 잘 따르지만 예시 문장을 그대로 베낄 수 있다. 이 안은 **넣지 않았다**.
